# Git 分支协作

先读项目 Git 规范，再查当前仓库、分支、远端及评审流程。初始化不固定分支策略或名称，不创建远端分支、修改保护规则或配置审核人；这些操作须由对应工具适配并回读验证。

## 分支与范围

确认目标仓库、工作树、远端、基线提交和任务范围，保留他人未提交修改。开发前按任务、用户明确目标、项目规范及远端元数据确定分支基线与合并目标。
主干、开发、测试、回归等分支用途及合并顺序由项目决定，不按名称猜测、不要求逐级合并；信息不足或冲突时澄清，不擅建测试、回归等长期分支。
分支创建、命名、清理及直接提交限制遵循项目约定与保护规则，不混入无关改动。

## 提交与评审

提交前检查暂存 diff，仅提交任务范围。标题写具体结果，正文写原因、范围、验证及风险；语言、格式按项目约定，不强加语言、章节数或编号格式。工作项编号须有真实记录。
PR/MR 复用 Change 的问题、方案、影响、证据、风险及回滚，不重复正文；工作项关联按平台策略。
评审人、合并方式、CI、保护分支要求按项目政策。验证目标分支最新临时合并结果及相应隔离 CI，本机通过不替代必需 CI；远端未回读记 not_evaluated，不宣称可合并。

## 合入与恢复

推送、合并、发布遵循任务已有授权及平台适配流程；合并前核对目标和源提交仍匹配审批/验证对象。失败或结果不明先回读，不重复有副作用操作；合并后核实实际提交与状态，按项目约定清理自己的短期分支。
不擅自 force push、重写已有提交或丢弃他人修改；冲突先定位归属。按项目允许的 revert、回退制品或恢复流程回滚并验证，不能遗漏热修复同步。
