# UI 对齐：视觉契约驱动验收

修改前读取设计文档、截图、原型、组件规范或用户指定对标产品，作为验收依据并记录版本、页面及状态；不得从当前实现反推目标契约。
无设计资料时沿用项目已确认 UI 规范；影响产品选择的缺口或冲突先澄清，不自造视觉目标。

## 设计到验收

用 `.wisharness/templates/visual-contract.md` 记录结构、内容、交互状态、可访问性、几何、颜色圆角、响应式断点及关键截图。沿用项目实际 UI 测试入口，不指定框架或宿主。
实现前将可自动验证目标写成 UI 验收测试，运行并确认因未对齐而失败；其余列人工验证步骤。优先按可访问角色、名称、可见文本定位，覆盖错误、空状态、加载、恢复及关键尺寸。

## 判定

- 结构、可访问性、可操作性、内容溢出及关键断点错误为硬失败，功能 E2E 通过不等于视觉对齐。
- 几何容差取自契约或 capabilities.settings.ui.tolerancePx；无值记 not_evaluated，验收前确定。截图阈值按目标平台、字体、渲染环境分别确定，不预设统一像素或差异比例。
- 已批准容差内差异记 advisory 并提醒；超阈值则失败或明确交人工裁决，不擅自放宽。
- 缺目标平台基线记 not_evaluated；补齐前不得宣称该平台视觉验收或相关发布门禁通过。

## 证据

保存结构化报告、独立可查报告、关键状态截图及哈希，注明设计来源、提交、平台、视口和测试命令。目录、报告格式沿用项目工具；原始证据不含秘密，按项目文档生命周期保存，Change 仅链接结论与证据。
分别报告功能通过、视觉通过、advisory、人工待审、未评估；必需门禁未通过不得宣称 UI 完成。
