# 团队协作

适用于行为变更、并行协作、交接；纯问答、只读排查及不写仓库的临时实验不建记录。先读项目协作规范及 `.wisharness/config.json`，复用已有真源，不建重复控制面。
发现复用、验收澄清、选测、TDD 与完成证据遵循 core 基础规范；本规范只补充记录、协作与交接要求。

## 发现与复用

按基础规范完成发现复用，另查进行中工作，先收敛重复工作；共享变更包记录 reuse、extend、replace 或 new 及依据。读取目标目录规则，核对基线、工作树和他人未提交修改。

## Change 真源与共享变更包

沿用项目已有需求、任务或 PR/MR 作为 Change 真源，实现前明确目标与验收，实际结果随执行更新。不强制创建远端工作项、单独的 Change 文件或新的状态系统。
小型局部变更可用持久化任务描述或 PR/MR 正文，只记本次目标、关键约束、验收及结果，未完成时补下一步；无需逐项填写共享变更包模板。不因记录简化降低基础规范的验证要求。

以下情况建共享变更包：跨会话、跨 PR/MR、跨仓库或多执行者需共享资料；跨模块需共同维护契约或验收方案。优先沿用目录与编号约定，否则用 `docs/changes/<change-id>/change-record.yaml` 和稳定唯一的 `CHG-<简短主题>`；先搜索记录，同一变更复用 ID 与真源。
共享变更包须含目标与验收、执行者、基线、影响、验证证据及剩余事项；涉及需要恢复的状态或发布时补充回滚。复用决策、评审与依赖按实际需要补充，已有内容直接引用。
模板 `.wisharness/templates/change-record.yaml` 是可裁剪的字段参考；只保留本次适用字段，不为无关事项填写 unknown/not_applicable。实际变更包由项目维护，不属插件托管文件。

spec/plan 的使用与存放遵循基础能力的[设计与任务拆分](method-design-planning.md)。共享变更包复用同一需求目录，已有文档直接引用。
目标、行为、验收及方案正文只维护一处，其余位置保留摘要和准确引用（文件章节或场景），不能两边都只放链接。Change 中的对应字段可用摘要和引用，不重复展开 spec/plan；验收沿用已有场景或 ID，不因使用模板额外要求编号或 YAML。状态、实际验证证据与剩余事项统一记录在 Change。
计划和 PR/MR 引用 Change 状态与结果，不复制进度；个人临时 TODO、原始日志不入共享变更包。

## 推进与更新节点

1. 实现前：按基础规范明确验收与待澄清项；共享变更包的验收场景写入口、操作、预期结果，绑定目标测试或人工验收并声明预期影响与依赖。存在并发冲突时再协调认领。
2. 实现中：需求、方案、接口、依赖或范围变化时，先更新真源、相关契约及受影响验收，再继续依赖步骤。聊天新结论不得长期脱离共享记录。
3. 验证后：按实际 diff 复核 direct/transitive/unknown 影响与消费者，补齐遗漏场景；逐项记录命令、退出码、提交或工作树基线、环境、证据位置及结果。分别说明失败、未执行、外部阻塞，保留剩余事项与下一动作。
4. 评审与交接：评审改变方案、影响、证据或已知缺口时更新真源。中断、换人或跨会话记录恢复点、剩余工作及下一条验证命令；接手者先读 Change，再核对当前代码与依赖，不以旧证据代表现状。
5. 合入与收尾：回读实际合入提交，发布另记环境与证据；按文档生命周期迁移长期契约、保留结果摘要、清理过程资料。

状态沿用项目工作项流程，无约定时可参考模板的阶段。只标记有证据的实际状态，无 MR 或发布环节时按约定验收结束，不补造阶段。返工、取消、替代和阻塞记录原因与下一步，未完成工作保持可见；`merged` 不等于 `released`。

## 认领与并发

单执行者且无共享写入冲突时省略 Claim，无需填写不适用理由。存在多执行者对同一文件、接口、数据结构或发布配置的冲突修改时，先通过项目已有协作渠道明确范围、责任人和有效期，解决冲突后再编码。
认领状态以真实协作渠道为准。没有共享认领服务时，通过已确认的任务边界隔离修改或串行协调，不把个人文件冒充原子租约。多 Agent 并行须有任务授权，安装本规范不要求或授权委派。

## 验证、评审与交接

沿调用者、消费者、数据、平台、发布边分析影响；未知消费者、Owner 或测试记 unknown/not_evaluated，说明影响、补验与阻塞条件，不以空字段或本机成功代替未知边界验证。跨仓库变更确认接口提供方、消费方及合入顺序，记入现有 Change。
必需测试与评审完成后按项目 Git 流程合入；评审数量、平台保护遵循项目政策，不预设人数。
用 `.wisharness/templates/handoff.md` 交接基线、已完成/未完成、证据、冲突、下一步与恢复点。接手先核对当前工作树和依赖，再复用仍有效的证据；已完成任务不因会话变化重新执行。涉及数据、环境或发布状态变更时给出可执行回滚并验证适用恢复结果，文档或签字不替代执行证据。

## 文档生命周期

一条事实一个真源，其余链接引用。临时步骤、原始证据存项目已确认忽略的目录或外部制品库；共享状态、跨会话必要方案、长期契约按项目约定版本化。无目录约定时分别用 `.scratch/<change-id>/`、`.artifacts/<change-id>/`，写前核实 Git 忽略，否则先建立忽略约定或存工作区外。
结束后：长期契约迁领域文档，可复用取舍迁 ADR，Change 留最终证据链接或摘要；删除无长期用途的实施步骤，保留的历史方案须归档、链接当前契约且不再作为当前行为依据，去向记 `document_exit`。
Git 忽略不保护秘密；凭据和未脱敏数据不得进 Change、模板、日志或报告。

本协议由 Agent 与评审执行。初始化只装规则、模板，不建空变更包、不自动更新 Change 状态；治理检查、CI、共享认领服务须另接，并以真实执行证据证明门禁通过。
