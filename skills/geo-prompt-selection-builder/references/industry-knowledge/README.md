# 行业知识档案

`scripts/industry_kb.py` 每做完一个客户的选词，把品类层面的经验并进这里。两层：

- **品类**（英文品类词，如 dash cam）：约束条件、目标客户、使用场景、主题划分、品类叫法，生成 `品类-<品类>.md`。
- **行业**（precollect-channels.json 的行业键）：渠道效果（评价站、社区是按行业选的），加上跨品类、2 个以上客户都出现的条目，生成 `行业-<行业>.md`。

数据一个行业一份 `<行业>.json`；`.md` 都是自动生成的，不要手改。

- 只存品类层面的条目；不存品牌名、竞品名、域名、买家原话和客户资料。
- 同一条在 2 个及以上客户出现标「通用」，只出现过 1 次标「单例」；写法只差连接词、标点、空格的算同一条。
- 同一品牌同一市场重跑以最近一次为准（换了行业或品类会从旧档案撤掉）；同一品牌不同市场合起来算 1 个客户。
- AI 读本行业的「行业-」和最接近本客户品类的「品类-」两份，只当假设级线索查漏，要用本客户的买家信号核实（selection-rules.md → 2「以前客户积累的经验」）。
- 本目录随 skill 发布，是积累的起点。平台部署时用 `GEO_INDUSTRY_KB` 指到持久化目录：第一次运行时从这里复制一份，之后在那里积累，每次运行前拷进工作目录给 agent 读（runner-ops.md）。
- 客户只记品牌名的哈希，不存品牌名。
