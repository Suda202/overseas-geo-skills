# 其他提示词类型：替代、对比、评价、问题解决

本文件写四种暂不开放的类型。本期只做发现型可见度（selection-rules.md → 1），这四种的行只登记、不出题、不进主题。重新开放竞争定位、声誉与信任或问题解决后，按本文件启用，主流程不改。

**和发现型的共同点**：每行只有一种提示词类型；题的类型就是所在行的类型（门禁 61）；行的业务优先级、写题方法都照 selection-rules.md；一个主题只放一种类型（selection-rules.md → 6）。本文件只写四种类型各自不同的部分。

## 什么时候开行

只有发现行用查漏清单开。其他类型有证据或合理假设才开，不为每个任务把五种类型都开出来。替代、对比行的开行依据写明是哪家竞品、哪条信号，写在业务优先级依据里（「……。开行依据：销售记录里常拿 Navan 比」）。

| 类型 | 什么时候开行 | 旅程阶段默认值 |
|-|-|-|
| 替代 | 有买家在用、在考虑或想换掉某个具名竞品的说法（「X alternative」搜索、社区换平台帖、销售记录），或写得出的合理假设 | 方案考虑 |
| 对比 | 有买家拿品牌和具名竞品比的证据（「X vs Y」搜索、社区对比帖、销售记录），或合理假设 | 购买决策 |
| 评价 | 买家在问品牌可不可信（scam、legit、reviews 搜索，社区里问口碑） | 购买决策 |
| 问题解决 | 问题型搜索词（how to、why、怎么办）、社区求助帖、核心目标客户与购买场景里点名的问题 | 需求认知 |

- **阶段取默认值，可以改**：买家处境明显不同时人工改。
- **业务优先级默认跟同任务的发现行**：同一个任务的其他类型行默认取它发现行的档位，不一样时在依据里写理由；这个任务没开发现行的照常判。
- **假设沿用现行批准路径**：标假设开的行照常出题、试跑，出题原因写明「假设：……」；品牌方在提示词库把题标成「已批准」就算确认。

## 出几道、读什么

| 类型 | 出几道 | 读什么 |
|-|-|-|
| 替代 | 每个有依据的竞品 1 道；同一竞品只有购买任务会改变候选时才按任务拆 | 提及率，单独报告，不计入考核（口径见 selection-rules.md → 1） |
| 对比 | 每个有依据的竞品 × 使用场景 1 道，场景取这一行最关键的 | 胜负 |
| 评价 | 每个使用场景 1 道，买家口吻 | 判断、优缺点、正负面 |
| 问题解决 | 每个具体问题 1 道；占正式名额 | 引用；不导出上传 CSV，读数只在基线 HTML 报告里 |

对比、评价、问题解决按上表的数出，不另设总数上限。旅程阶段在行上按类型取默认值，可以改。

- **评价题不计入考核**：正向情感占比只报告、不承诺，口碑主要靠第三方信源，品牌自己难推动；声誉与信任没开放时，品牌和竞品的优缺点看第 2 步调研预跑就够。
- **问题解决默认不出**：how-to 问法大概率不提品牌，只看品牌页有没有被引用（不计入考核）。
- **什么算品牌方点名问题解决**：品牌方自己写的核心目标客户与购买场景里有问题型诉求（怎么做、怎么避免、要注意什么），就算。我们代填的不算，品牌方确认后才算；搜索词、社区帖里问题型的说法再多也不算，它们只用来开相应买家处境的矩阵行，留给基线后的内容计划。
- 发现、对比、替代分别出题不算重复，读的是三个指标：进不进名单、二选一谁赢、换掉某竞品时进不进名单。去重只在同一类型里做。

## 题面怎么写

- **替代题只点名一个竞品、不写本品**，问它的替代选择。也可以替代一种现有做法，不限于竞品产品（在用的服务商、手工流程都算），同样要有买家想换掉它的证据或合理假设；题面写清当前做法、想解决的限制、要哪一类候选。保留真实意图，不为了让答案多列品牌而把「换掉 X」改写成另一个任务。
- **对比题带明确的决策依据或使用场景**，根据真实买家任务表达；胜率同时报含平局和去掉平局两个数，看去掉平局的。
- **评价题用买家口吻**：「Is [brand] worth it for [use case]?」；「Evaluate …」的报告式问法只用于调研预跑。
- 条件、不诱导、一题一个决策、去重规则同 selection-rules.md → 7「题面怎么写」。
