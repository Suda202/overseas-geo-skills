# 其他意图类型：问题解决、评估、对比、替代、验证、交易、售后

八类意图类型的定义、英文键和题面品牌词规则见 selection-rules.md → 5「意图类型：八类」。本文件写发现以外七种暂不开放的类型。本期只做发现型可见度（selection-rules.md → 1），这七种的行只登记（写进题库 `config.slices`，开行依据照写），不判业务优先级、不进对客确认表、不出题、不进主题。重新开放对应目标后，按本文件启用，主流程不改。

**和发现型的共同点**：每行只有一种意图类型；题的类型就是所在行的类型（门禁 61）；开放后行的业务优先级、写题方法都照 selection-rules.md；一个主题只放一种类型（selection-rules.md → 6）。本文件只写各类型不同的部分。

## 什么时候开行

只有发现行用查漏清单开。其他类型有证据或合理假设才开，不为每个任务把八类都开出来，也不为覆盖完整旅程出题。替代、对比行的开行依据写明是哪家竞品、哪条信号，写在题库行的 `priority_basis` 里（「开行依据：销售记录里常拿 Navan 比」）。

| 类型 | 什么时候开行 |
|-|-|
| 问题解决 | 问题型搜索词（how to、why、怎么办）、社区求助帖、核心目标客户与购买场景里点名的问题 |
| 评估 | 买家在问本品适不适合某用途、有没有某项能力、兼容不兼容（「is X good for」「does X support」搜索，社区里问适用性，销售常被问的能力问题） |
| 对比 | 有买家拿品牌和具名竞品比的证据（「X vs Y」搜索、社区对比帖、销售记录），或合理假设 |
| 替代 | 有买家在用、在考虑或想换掉某个具名竞品的说法（「X alternative」搜索、社区换平台帖、销售记录），或写得出的合理假设 |
| 验证 | 买家在问本品靠不靠谱（scam、legit、reliable、complaints、reviews 搜索，社区里问口碑和投诉） |
| 交易 | 独立站电商，或品牌方点名转化渠道（官网直购、指定经销商）；不点名问哪里有货的，只在品牌方点名时开 |
| 售后 | 品牌方把客服或留存列为目标，或客服工单、差评里集中出现某个问题；品牌不负责的服务不开行（找房平台不管交易后的产权办理） |

- **假设沿用现行批准路径**：标假设开的行照常出题、试跑，出题原因写明「假设：……」；品牌方在提示词库把题标成「已批准」就算确认。

### 对应哪个目标

| 目标 | 意图类型 | 什么时候出 |
|-|-|-|
| 发现型可见度 | 发现 | 本期唯一开放的目标，见 selection-rules.md → 1 |
| 竞争定位 | 对比；替代 | 该目标开放后（启用方式待定），并且有买家在比较或想换掉某竞品的证据 |
| 品牌呈现 | 品牌事实核查记录；准确性题（八类之外，见 `geo-monitoring/references/trial-and-lock.md`「零提及怎么诊断、准确性题」） | 核对关键事实、来源和错误，单独跟进修正 |
| 声誉与信任 | 评估；验证 | 该目标开放后（启用方式待定），并且买家在问本品适不适合、靠不靠谱 |

问题解决看品牌方是否点名（见下「什么算品牌方点名问题解决」）；交易、售后不属于这四个目标，按上表开行条件开。

**目标开放后按目标和买家需求决定是否出题**：竞争定位可用竞品词搜索、社区对比帖、销售比较记录作为依据；声誉与信任可用可信度查询、社区疑虑、售前风险问题作为依据。证据不足时保留假设标记并请品牌方确认。预跑用于发现事实错误和调查线索，单次正负面表现、领先或落后均不改变准入。品牌呈现诉求进入品牌事实核查记录。出题原因说明需求依据，由品牌方批准后试跑。

### 业务优先级上限

**开放对应目标时启用，本期暂不执行**：本期这七类行只登记、不判档（selection-rules.md → 5「意图类型：八类」）。开放后判法同 selection-rules.md → 5「业务优先级」，另加一条上限：意图类型要和本期目标对得上。同一个使用场景，用不同意图类型问 AI 的人处在购买的不同位置：发现、替代还没选定品牌，能新获客；对比已经在拿本品和竞品比，争取被选；评估、验证已经知道本品，在决定买不买；交易、售后已经选定或已经买了；问题解决在找办法，不直接找品牌。先看品牌方本期要解决什么问题（核心目标客户与购买场景、品牌方写的相对弱项），再定这一类行最高能到哪一档：

- 品牌的短板是知名度（新品牌、大多数客户）：替代、对比可以和同场景的发现行同档；评估、验证最高中；交易、售后默认低；问题解决默认最高中，品牌方点名问题型诉求时可以和发现行同档。
- 品牌的短板是口碑或信任（AI 常说它不可靠、有投诉）：评估、验证可以和发现行同档。
- 品牌方把官网直购转化、客服或复购列为本期目标的：交易、售后可以提到中。

只定上限，不替代业务价值判断：在上限以内照常按商业价值、战略重要性、当前业务重点判，这个场景没开发现行的也照常判。依据里写明对的是哪项目标（「中：问的人已经知道 Bbrand；品牌方本期要解决的是知名度低」）。意图类型只按这条看它和本期目标对不对得上，不另外加减档。

## 出几道、读什么

| 类型 | 出几道 | 读什么 |
|-|-|-|
| 问题解决 | 每个具体问题 1 道；占正式名额 | 提及率（品牌是否出现在解决步骤里）；不导出上传 CSV，读数只在基线 HTML 报告里 |
| 评估 | 每个使用场景或能力 1 道，买家口吻 | 情感。适用类：AI 结论（推荐 / 有保留 / 劝退）、按属性归类的优缺点；能力类：AI 确认、否认还是不确定，对照官方事实 |
| 对比 | 每个有依据的竞品，按真实买家决策覆盖高价值使用场景和关键决策属性；不穷举属性，不强制每个场景都拆属性 | 胜负、情感 |
| 替代 | 每个有依据的竞品 1 道；同一竞品只有使用场景会改变候选时才按任务拆 | 提及率、情感 |
| 验证 | 每类有证据的信任疑虑 1 道（整体口碑、某类投诉、某项风险） | 情感：信任结论（可靠 / 有保留 / 劝退）、提到的投诉和风险、引用了哪些第三方来源 |
| 交易 | 每个产品线或主推型号 1 道 | 准确性：渠道、价格、库存说得对不对 |
| 售后 | 每个集中出现的问题 1 道 | 准确性：步骤和退换、保修政策说得对不对 |

七种都按上表的数出，不另设总数上限，都不计入提及率考核。「读什么」就是这一类的统计指标，由意图类型决定，不另设字段；引用所有类型都统计；准确性有没有品牌方资料判法不同。三条口径都在 shared/canonical-intent-mapping.md。

- **评估、验证不计入考核**：判断和正负面只报告、不承诺。声誉与信任开放前，要看品牌和竞品的优缺点时按需补跑评估预跑（selection-rules.md → 2）。
- **问题解决默认不出**：how-to 问法大多数回答不提品牌，首轮品牌还没写相关内容，提及率基数很小。
- **什么算品牌方点名问题解决**：品牌方自己写的核心目标客户与购买场景里有问题型诉求（怎么做、怎么避免、要注意什么），就算。我们代填的不算，品牌方确认后才算；搜索词、社区帖里问题型的说法再多也不算，它们只用来开相应买家处境的矩阵行，留给基线后的内容计划。
- 发现、对比、替代分别出题不算重复，读的是三个指标：进不进名单、二选一谁赢、换掉某竞品时进不进名单。去重只在同一类型里做。

## 题面怎么写

- **问题解决题不写品牌**，问通用的品类问题。
- **评估题用买家口吻，点名本品或型号**：「Is [brand] suitable for [use case]?」「Does [product] support [feature]?」；「Evaluate …」的报告式问法只用于调研预跑。买家明确说还没买、在看安装难不难的，也是评估。
- **对比题围绕真实买家决策写，并明确要 AI 推荐一家**：题面有两个具名品牌、明确的推荐要求（「Which would you recommend for [use case], A or B?」「Is A or B better for [use case]?」），再加一个比较条件。只写「A vs B」「Compare A and B」，AI 会两边都说，判读只能记平。
  - **比较条件选会改变最终推荐的**：高价值的使用场景（所在行的使用场景），或买家做决定时真正拿来比的关键属性（夜间画面、侧面覆盖、停车监控耗电）。选哪个看买家证据和它会不会让 AI 换一家推荐，不看品牌在这一项强还是弱。
  - **不穷举、不强拆**：不为每个属性各出一道对比题，也不要求每个场景都再拆成几道属性对比；一个场景下，只有不同属性会让推荐结果不同、且各有买家证据时才分开出。
  - 比较条件落在品牌明显劣势上的照写，题上记 `brand_weakness`，提示词优先级降一档（selection-rules.md → 7「品牌明显劣势」）。
  - 胜率同时报含平局和去掉平局两个数，看去掉平局的。
- **替代题只点名一个竞品、不写本品**，问它的替代选择。也可以替代一种现有做法，不限于竞品产品（在用的服务商、手工流程都算），同样要有买家想换掉它的证据或合理假设；题面写清当前做法、想解决的限制、要哪一类候选。保留真实意图，不为了让答案多列品牌而把「换掉 X」改写成另一个任务。
- **验证题点名本品，只问可信度**：「How reliable is [brand]?」「Are there common complaints about [brand]?」；问能力的归评估。
- **交易题**：点名本品问渠道（「Where can I buy [product] in [market]?」）；不点名问哪里有货的只在品牌方点名时写。
- **售后题必须写品牌、型号或服务名**（「How do I update the firmware on [product]?」）；不点名的归问题解决。
- 条件、不诱导、一题一个决策、去重规则同 selection-rules.md → 7「题面怎么写」。
