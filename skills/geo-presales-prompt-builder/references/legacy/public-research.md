# 售前公开调研

售前做完售后调研里公开的那一半，成交后售后在同一份多维表格副本上接着做（规则见 [共用原则](../../../shared/prompt-generation-principles.md) →「主题的两种来源」末段）。本文件只定义调研产物的格式和它在流程里的位置；收哪些来源、怎么判可信度、搜索词怎么改写成题面，都以售后的 [signal-sources.md](../../../geo-prompt-selection-builder/references/signal-sources.md) 为准，品牌事实核查的取舍以 [对客件规则](../../../geo-prompt-selection-builder/references/client-facing-attribute-pool.md) →「品牌事实核查」为准。

## 在流程里的位置

1. Case 归一化之后、生词之前做调研：买家原话决定属性的重要性和题面，规格页决定相对竞品与可改变性。
2. 原话收齐后先过 [主题发现](#主题发现case-之外还有哪些需求簇) 与 [品牌定位校验](#品牌定位校验品牌自述与市场实际说法对不对得上) 两遍，产物只留在本文件。
3. 生词时把三项判断写进 `attribute_plan`（见 [属性规划](attribute-planning.md)），每道题挂上支撑它的原话编号（写在调研文件的 `prompt_evidence` 里，不写进题库）。
4. 采集后，用 `scripts/export_to_confirm_base.py <题库> --research <调研文件> --market ... --copy` 写进模板副本。

## 文件格式 `presales-public-research/v1`

键名直接用多维表格的列名，导出时原样写入。

```json
{
  "schema_version": "presales-public-research/v1",
  "collected_at": "2026-01-01",
  "buyer_quotes": [
    {
      "输入编号": "Q01",
      "原话": "Any option that also covers the space I cannot see?",
      "中文意思": "有没有连我看不到的地方也能覆盖的方案？",
      "涉及品牌": ["未指明品牌"],
      "来源类型": "社区",
      "受众": "注重使用场景覆盖的个人买家",
      "旅程阶段": "发现",
      "约束": "额外覆盖范围",
      "来源说明": "社区，2026-01-01",
      "来源链接": "https://example.com/community/post",
      "证据可信度": "中"
    }
  ],
  "fact_checks": [
    {
      "事实项": "某项能力是否需要另外购买配件",
      "官方值": "…",
      "来源页面": "https://…",
      "冲突说法": "…",
      "冲突来源": "https://…（或「同页面 FAQ 区块」）",
      "品牌方要做什么": "改官网"
    }
  ],
  "scope_facts": [
    {"项目": "买家要完成的任务（1）", "内容": "…"}
  ],
  "topic_candidates": [
    {
      "候选主题": "…",
      "支撑原话": ["Q03", "Q07"],
      "与现有主题的关系": "在现有主题之外，买家还在问长期运行的供电与耗材",
      "独立购买意图条数": 6,
      "处置": "纳入本 Case"
    }
  ],
  "positioning_check": [
    {
      "模板格": "We win because …",
      "品牌自述": "…（官网原文，附来源页面链接）",
      "市场实际说法": "…（原话怎么写）",
      "对得上": "部分",
      "处置": "交品牌方确认"
    }
  ],
  "prompt_evidence": {"T1-D02": ["Q01"]}
}
```

- `受众` 取 Case 的目标客户或目标企业画像原值；没有细分人群时填品类基础人群，不写「通用」。
- `来源类型`、`旅程阶段`、`证据可信度`、`品牌方要做什么` 只用模板里的选项值，导出脚本遇到别的值会停止。
- `fact_checks` 每行必须有 `来源页面` 链接，没有链接不写这一行。
- `scope_facts` 只写公开层能定案的事实，例如带证据的差异化优势、买家要完成的任务；要问品牌方的写进属性的备注，不写在这里。
- `prompt_evidence` 只引用本文件里的 `输入编号`。没有挂上原话的题，导出时会列出来，按假设级看待。
- `topic_candidates` 与 `positioning_check` 只留在本文件供内部判断，不进题库、不进对客件。导出脚本只读 `buyer_quotes / fact_checks / scope_facts / prompt_evidence` 四个键，加这两个键不会被拦下，也不改变已经导出的表。

## 原话收齐后的两遍附加判断

两遍用的是同一批 `buyer_quotes`，问的不是同一件事：**主题发现问市场还需要什么，品牌定位校验问品牌说的和市场记得的对不对得上。** 前者看缺口，后者看落差，两边结论可以完全相反——某个需求簇市场很热但品牌确实不做，主题发现记「不采纳」，定位校验这边不需要出东西。不合并成一份结论，也不互为前置。

### 主题发现：Case 之外还有哪些需求簇

现有链路是 Case 字段 → 属性池 → 聚主题，属性池收不到的东西永远发现不了（Pbrand 池里几乎没有 P3 就是这个症状）。这一遍补反向动作：从已经抓到的原话里重新聚一轮，看有没有 Case 三个主题装不下的需求簇。

- 输入就是同批 `buyer_quotes`，不额外采集。
- 每个候选写清：支撑它的原话编号、为什么不在现有主题内、能形成几条彼此独立的发现型购买意图。
- 够 5 条的写「纳入本 Case」，不够的写明缺什么证据（写「证据缺口」而不是「不采纳」）；市场根本不需要的写「不采纳」并给理由。
- 如果某条原话**反驳**了 Case 里已有的主题假设（例如买家根本不按我们以为的维度选），单独标出来，别只当候选处理。
- 主题是 Case 必填项，改主题要走 Case 更新（见 [Case 主题生成规则](../../../geo-presales-eval-case-builder/references/topic-generation-reference.md)），这一遍只出候选，不直接改主题、不动题库。

### 品牌定位校验：品牌自述与市场实际说法对不对得上

品牌定位由品牌方定，调研不发明定位，只拿市场实际说法校验它。品牌自述取**官网首页、功能页和场景页上品牌方自己写的说法**——那是 AI 实际在读的原件，也是品牌方对外承诺的原文；Case 字段只是我们的概括，隔了一层，官网没写清的格子才回来查。

Profound AEO Guide Chapter 2 的一句话模板是 `We are a ___ for ___ who need ___ . We win because ___ . We are not ___ .`，五个空对应我们官网上的这几处：

| 模板格 | 主要取自 | 官网没写清时 |
|---|---|---|
| We are a ___ （品类） for ___ （受众） | 官网首页的自我描述 | `品类`、`目标企业画像 n` / `目标客户 n` |
| who need ___ （核心能力） | 官网功能页、场景页 | `痛点 n`、`使用场景 n`、`产品特性 n` |
| We win because ___ | 官网的差异化主张 | `差异化优势` |
| We are not ___ | 官网的适用条件或排除说明 | `适用边界` |

做法：

1. 先照官网把五格填成一句完整承诺，每格附上来源页面链接；填不出来的格子记下来，不要编。
2. 再读原话，看市场实际怎么描述这类品牌、怎么说自己的需求——同一批来源就是 AI 在读的来源。
3. 逐格判 `对得上 / 部分 / 对不上`，写清差距是什么。
4. **差距不等于错误，它是「要不要改定位」的判断材料**：原话说的关注点和品牌自述不一致，可能是自述太宽（AI 会把它压成「对谁都合适、对谁都不最优」），也可能是定位本身站不住，要交品牌方定，不自行改写。
5. 处置只写两类：交品牌方确认，或进 `fact_checks`（事实层面的冲突走那边）。
