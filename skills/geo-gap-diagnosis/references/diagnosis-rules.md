# 诊断规则

本文件定义从采集读数（售前、试跑或正式基线）到「优化机会」的全部判定。阈值都是参数（`scripts/diagnose.py` 顶部 `PARAMS`），第一版按 Housebell、路拓两个客户定，积累客户后再校准。方法来源与证据强弱见 [evidence-base.md](evidence-base.md)。

## 1. 七层读数

每道题 × 每个平台、以及跨平台合并，各出一组读数（`scripts/layer_readings.py`）。七层不是漏斗：可以被引用却没被提及，也可以被推荐但说错。

| 层 | 读数 | 能不能观察 |
|---|---|---|
| 可达 | 官网在任何回答的检索或引用里出现过 → 实测可达；从没出现 → 读官网诊断报告，没有报告记「未知」 | 部分 |
| 联网 | 回答有没有检索 | **ChatGPT 采集用 `web_search=true`，Scrapeless 文档写明这会让 ChatGPT 执行搜索，Housebell、路拓两批实测 100% 都有 `search_result`：联网是被强制的，自然联网率不可观察**。读数记「强制联网」，本层判「未知」 |
| 检索 | 官网（或某 SKU 页）进检索结果的回答占比 | 有检索字段的平台：ChatGPT `search_result`、AI 模式 `search_result`、AI 概览 `web_source`、Copilot `links`、Grok `web_search_results`；Gemini、Perplexity 不可观察 |
| 引用 | 官网被正文引用的回答占比 | 全部平台 |
| 提及 | 本品、竞品在去引用正文里出现的回答占比；首次出现顺序 | 全部平台 |
| 推荐 | 本品被提及时的推荐状态分布 | 模型标注，见 [recommendation-labels.md](recommendation-labels.md) |
| 准确 | 回答里关于本品的事实错误 | 模型标注，对照品牌事实表或约束条件表 |

所有比率都带分母和 Wilson 95% 区间。跨平台合并只用于判稳定性和排序，结论按平台分开写；平台方向相反时不合并成一句。

## 2. 三道门：先判是不是值得做的机会

按顺序过，前一道不过就不再往下判，直接给决定。

| 门 | 判据 | 不过时的决定 |
|---|---|---|
| 0 样本 | 合并有效回答 ≥ `min_valid`（默认 7） | 观察：样本不足 |
| 1 业务价值 | 题所在主题的业务优先级为高或中 | 暂不做：业务优先级低 |
| 2 产品适配 | 题的主约束在约束条件表里「相对竞品」不是「明显劣势」；推荐标注里本品的「有条件不推荐」原因不是真实能力缺失 | 转产品：写明哪项能力或条件缺失 |
| 3 缺口稳定 | 合并读数里，提及率最高的同类竞品区间下限 > 本品区间上限；或本品提及率 ≥ `mention_ok` 而推荐占比 < 50%（标注 ≥3 条） | 观察：差距在区间内，下一期再判 |

业务优先级缺失（题库和 Base 都没写）时记「未定」，不拦，但诊断说明里列为待补。相对竞品缺失时记「未判」，不拦。

按题型分开处理：

- **不点名的发现题、替代题**：走完三道门和下面的断点表。答案基本不点名任何同类品牌（领先品牌提及率 < `no_brand`，默认 20%，本品也低于它）的，提及率测不出东西，不判「守住」：答案里别的品类品牌（词表 `same_category: false`）被提到一半以上的，是**品类错位**；否则是解释模式，改按下一条的引用缺口判，并提示回选词复核题面是否在问候选。
- **品类错位不改题面、也不直接放弃**（Suda 2026-11-16）：题是真实买家问法，为了让品牌出现去改题等于改尺子。先判本品能不能真的替代这个品类（服务路径，定义见选词 selection-rules 第 3 步）。被引第三方页面里已经有提到本品的（页面缺口检查里 `target_on_page`），记「6 答案缺口（品类替代）」，决定测试：官网写如实的品类对照页，请已提到本品的被引页面补替代说明；预期放低，目标是作为替代选项被提到，不是赢过该品类的领先品牌。被引页面里没有本品的，记「品类错位」，决定先补研究：能替代就转测试，不能替代就回选词改为只监测或删题。业务优先级低的照样暂不做。
- **不点名的其他类型**（问题解决、信息类）：答案通常不列品牌，不判提及缺口，判**引用缺口**，目标是让官网成为被引来源。来源分三类：机构（政府、百科）、社区（Reddit、社媒、视频）、其他（门户、攻略、媒体、厂商，品牌能争取的位置）。
  - **非机构席位** = 引用了至少一个「其他」类来源的回答占比。低于 `seat_min`（默认 40%）说明引用位基本被机构来源占满，记「暂不做」（门 2）。**机构站排第一不等于做不了**：一条回答常同时引政府站讲规则、攻略站讲做法（Housebell 20 道信息题里 17 道政府站排第一，但攻略站在 60% 以上的回答里有席位，Suda 2026-11-16 定按席位判）。
  - 门 3 用官网被引率和非机构席位比：席位区间下限高于官网上限才算缺口（席位常分散在多个攻略站，和单个站比会把缺口漏掉）。守住仍按「官网被引率 ≥ 被引最多的非机构来源 − `hold_margin`」。
  - 断点只看 1、3、4；动作参照被引最多的非机构来源页面。回答里的事实错误照样进事实行。
- **点名的评估题**：不判提及，只判推荐。被提及回答里「有条件不推荐」加「劝退」占一半以上才算缺口（第 7 断点）；只是事实陈述（仅列举）不算。
- **点名的对比题**：看胜负，不看推荐占比。本品被首推的回答数 vs 竞品被首推的回答数；竞品首推 ≥ 一半且多于本品，记「7 对比输」，决定先补研究：先读竞品胜出理由，硬规格差距转产品，证据缺口补如实的对比页。
- **点名的验证、交易、售后题**：只看劝退和事实错误，劝退不到三成记「不适用」。
- **守住**：本品提及率 ≥ 领先竞品 − `hold_margin`（默认 10 个点），且推荐占比 ≥ 50%；点名题推荐占比 ≥ 50%。

**事实错误单独成行**：按品牌事实表的编号（F-01、F-02…）跨题汇总，同一条事实在 ≥ `min_fact_errors`（默认 2）条回答里写错就成一个机会，决定「测试」，不受业务优先级门限制（错误事实先修）。题行里只在次要发现里注明「见事实行」，不重复开机会。

**SKU 单独成行**：品牌方给了 SKU 清单和适配题时，每个 SKU 跨它的全部适配题合并判一次（单题 7 次区间太宽，SKU 问题本来就是跨题的）。门 3 改为「品牌提及率区间下限 > SKU 出现率（正文或商品卡）区间上限」；断点按 SKU 页的进检索率、被引率和被引第三方页面有没有这个 SKU 判（3、4、5）。分母只算适配题的回答。

## 3. 第一断点

过了三道门的题，按下表从上往下找第一个成立的断点，只写一个主原因。后面成立的断点写进「次要发现」，不另开机会。**断点 1–6 只在本品提及率落后时查**（门 3 是因为领先竞品区间下限高于本品上限才过的）；提及率不落后、只是没被推荐的题直接从断点 7 判，免得把「官网没进检索」安到一道品牌每次都被提到的题上。

| 顺序 | 断点 | 成立条件（合并读数，只用可观察平台） | 证据强度 |
|---|---|---|---|
| 1 | 抓取不可达 | 官网诊断报告爬虫可达性为低 | 实测 |
| 2 | 不联网 | 有可观察的联网字段且联网率 < `ground_low`（默认 50%）。强制联网采集下不成立，记未知 | 实测 |
| 3 | 官网没进检索层 | 有检索字段的平台里（可观察回答 ≥ `min_retrieval_n`，默认 5 条），官网进检索率 < `retr_low`（默认 20%） | 实测；整批数据里官网从没进过检索或引用、又没有官网诊断报告时降为「推断：可达性未核」 |
| 4 | 进了检索层没被引用 | 官网进检索率 ≥ `retr_low`，官网被引率 < 进检索率 × 0.5 | 实测 |
| 5 | 页面缺口 | 本题被引 ≥ `page_min_cites`（默认 2）次的第三方页面里，有页面提到 ≥2 家竞品、没提本品 | 实测（需跑 `page_gap.py`）；没跑记未知 |
| 6 | 答案缺口 | 被引第三方页面提到了本品，引用它的回答却没提本品 | 同上 |
| 7 | 被提及但没被推荐 | 不点名题：本品提及率 ≥ `mention_ok`（默认 30%），被提及回答里推荐（推荐 + 首推）占比 < 50%；点名题见上 | 模型标注，抽检后算实测；主要状态是「有条件不推荐」时证据强度记「需核对约束是否属实」，决定为先补研究 |
| 8 | 被推荐但说错 | 走事实行，见上 | 模型标注，人工核对每一条 |

没有一个断点成立时，断点记「未定位」，决定为「先补研究」，写明缺哪项证据（常见：没有官网诊断报告、没跑页面缺口、平台不暴露检索层）。

断点 3 和 4 只在有检索字段的平台判。Gemini、Perplexity 这类平台上同一道题的缺口，原因写「检索层不可观察」，按断点 5–7 判。

## 4. 决定

| 决定 | 什么时候 |
|---|---|
| 测试 | 断点成立且证据强度为实测；做一个有边界的动作 |
| 观察 | 样本不足或缺口不稳定 |
| 先补研究 | 断点未定位，或主断点证据是推断 |
| 守住 | 已领先，见第 2 节 |
| 暂不做 | 业务优先级低 |
| 转产品 | 产品不满足推荐标准，内容改不了 |

## 5. 动作四要素

决定为「测试」的机会必须写全四项，载体只选一个：

| 字段 | 写什么 |
|---|---|
| 缺口 | 一句话，带数字：哪道题、哪个平台、哪一层、本品和领先者各多少 |
| 载体 | 官网 / 第三方页面 / 社区 / 分布式资料（伙伴、经销商、数据源）四选一 |
| 信息怎么变好 | 改哪一页、补哪条事实或证据；先写站内最接近的现有页面 URL（脚本给候选，人确认），没有才写新建 |
| 近端预期效果 | 动作生效时最先变的那个读数（见第 6 节主指标） |

各断点对应的动作写法见 [gap-cause-action-table.md](gap-cause-action-table.md)。

## 6. 度量契约

每条「测试」在交出前写好，复测时先看主指标：

| 断点 | 主指标 | 最早复测 |
|---|---|---|
| 3 官网没进检索层 | 官网（或目标页）进检索率 | 上线后 14 天 |
| 4 进检索没被引用 | 官网被引率 | 30 天 |
| 5 页面缺口 | 目标第三方页面是否已提到本品；其次本品提及率 | 页面更新后 30–60 天 |
| 6 答案缺口 | 本品提及率 | 30–60 天 |
| 7 提及未推荐 | 被提及回答里的推荐占比 | 30–60 天 |
| 8 说错 | 同类事实错误条数 | 错误来源改正后 30 天 |

- **对照题组**：同主题里本期不派动作的题；同主题没有就写「无可比对照」，结论降为方向性。
- **复测条件**：同一套题、同一平台和市场、同一采集参数（含是否强制联网）、同样次数；口径不同的读数不比。
- **五种结果**：符合预期 / 无明显变化 / 矛盾（如引用升、推荐降）/ 变差 / 证据不足。变化落在两期区间重叠内记「无明显变化」。无变化时按触达、执行、机制、信息、结构、时机、波动、度量、诊断本身九项排查。
- 报告写清什么没变；平台方向不同分开写。

## 7. 不作为诊断结论的东西

- 单次回答的排名位置；只报出现率和位次分布。
- 多平台合成的一个分。
- 加 Schema、加表格列表、llms.txt 当作提升动作（见 evidence-base.md「降级」）；Schema 缺失只在可达与实体一致性检查里作为基线项提。
- query fan-out 子查询当作买家需求；它只说明机器检索行为。

## 8. 竞争难度与优化难度（`scripts/difficulty.py`，Suda 2026-11-20）

给品牌方挑主题、给我们判断能不能把效果做上去。每道提示词、每个主题各出两个判断，分开写、不合成一个分，业务优先级另看。3 次试跑、正式基线能跑；每题有效回答不到 3 条（售前每题 1 次）不判：1 次回答里出现的每家竞品都算「每次都在」，轮换位恒为 0，会把所有题判成高（Zhiqinghe 2026-11-26，59 道题里 57 道判高）。3–6 条标「预判」，正式基线跑完再定。售前要给难度时，按回答内容人工判（候选是哪类供应商、AI 引用的是不是厂商官网、品牌有没有对应事实），写进诊断，不用这个脚本。只判不点名本品的题（发现、替代、问题解决），点名题写「不适用」。

- **竞争难度**：别家把这道题占得多牢。回答的是「位置还剩多少」，不是「本品现在多少」。
- **优化难度**：只改官网，把本品做进回答有多难。回答的是「我们做不做得上去」。

两者都不预测能涨几个点：公开资料里没有证据表明这些读数能预测优化后的涨幅（evidence-base.md「难度」），第一版阈值等积累 2–3 个客户的复测再校准。

### 8.1 提示词的竞争难度

先数两件事（品牌只算词表里 `same_category` 的同类品牌，本品也算）：

- **每答列几家**：每条回答点了几个同类品牌，取中位数；分平台另列一份（平台之间差得多，Peec、Semrush 都按平台看）。
- **固定竞品**：在 ≥80% 的回答里都出现的竞品（Indig「5 道里至少 4 道」用到单题的多次回答上）。

**轮换位 = 每答列几家 − 固定竞品家数**，是新品牌能挤进去的位置（Semrush：竞品强度 × 可得位置）。

| 条件 | 竞争难度 |
|---|---|
| 点了任一同类品牌的回答 < 20% | 不判：答案在讲方法或规则，先复核题面 |
| 每答列几家中位数为 0（多数回答不点品牌，点了的只列一两家） | 中 |
| 轮换位 ≤1 | 高 |
| 轮换位 ≥3 | 低 |
| 其余 | 中 |

依据一并写出固定竞品是谁、每答列几家、轮换位几个。

### 8.2 提示词的优化难度

按顺序判，命中即定档：

| 顺序 | 条件 | 优化难度 |
|---|---|---|
| 1 | 竞争难度为「不判」 | 不判 |
| 2 | 本品提及率 ≥30% | 已达标：任务是守住（考核看提及率，不看排第几） |
| 3 | 可改变性为低（品类错位、硬规格劣势、第三方主导，规则见 `geo-monitoring/references/changeability-and-order.md`） | 高，写出原因 |
| 4 | 本品提及率 ≥20%：已进候选 | 低 |
| 5 | 竞争难度高 | 高 |
| 6 | 竞争难度低 | 低 |
| 7 | 可改变性为高（同类竞品官网被引明显领先，改官网有直接参照） | 低 |
| 8 | 其余 | 中 |

已进候选排在竞争难度之前：三份数据里本品出现时其他品牌数没有变少（路拓 2.1 对 2.1、老虎 HK 4.6 对 4.6），本品进答案是多占一个位置，不一定要挤掉固定竞品。没给可改变性时第 3、7 步跳过，依据里写明。

### 8.3 主题

- **竞争格局**：某竞品在一道题里提及率 ≥50% 算「出现」。在 ≥80% 的题里都出现的是固定品牌（Indig 的主题口径）。只有一家固定、且声量份额领先第二名 ≥5 个百分点 →「单一主导」（Indig 的 clear owner，次月 90.4% 仍保持第一）；只有一家固定但份额没拉开 →「一家固定」；两家以上 →「多家固定」；没有固定品牌但领先品牌在 ≥50% 的题里出现 →「有领先者」；否则「未定」。点了同类品牌的回答 <20% 或每答列几家中位数为 0 →「多数回答不点品牌」，竞争难度不判。
- **竞争难度、优化难度**：取主题内题的多数档（高或低过半才定高或低，否则中），同时写分布，不取平均；优化难度有一半以上的题已达标时，主题记「已达标」。
- **可先做的题**：主题内优化难度为低的题。品牌方按主题挑，题只用来说明先做哪几道、官网该写什么。

### 8.4 产物

`difficulty/` 下 `prompts.csv`（每题：竞争格局、竞争难度及依据、优化难度及依据、本品提及率、领先竞品、领先份额差、前三竞品份额、每答列几家、分平台每答列几家、可改变性）、`topics.csv`、`difficulty.md`（主题表在前、提示词表在后）、`difficulty.json`（含阈值）。对客只用中文结论和依据，不出参数名。`difficulty.json` 每行另带 `detail`（原因代码、固定竞品、每答列几家等结构化读数），基线 HTML 报告由 geo-presales-report-builder 的 `attach_difficulty.py` 据此写成对客说法（本品提及率 ≥30% 的题在报告里记「低」、写「AI 常推荐的品牌之一」，不出现「达标」「守住」）。
